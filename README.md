# Träningsdagbok / Training Diary

🇸🇪 [Svenska](#svenska) · 🇬🇧 [English](#english)

## Svenska

En delad träningsdagbok för familjen, byggd som **en enda HTML-fil** (`index.html`) som kan läggas på telefonens hemskärm som webbapp. Data lagras live i en Firebase Realtime Database och delas mellan alla som har samma delningskod.

**Live:** https://griminell.github.io/training/

### Vad finns i repot?

| Fil / mapp | Innehåll |
|---|---|
| `index.html` | Den färdiga appen. **Det är den här filen GitHub Pages visar.** Genereras av `build.py` – redigera den inte för hand. |
| `src/App.jsx` | Själva appen: formulär, månadslista, statistik, användarhantering, teman, ändringslogg. |
| `src/main.jsx` | Start, uppsättningsskärm och lagringslagret mot Firebase (REST + SSE, utan SDK). |
| `src/styles.css` | Tailwind-direktiv och grundläggande CSS. |
| `tailwind.config.js` | Tailwind-inställningar. |
| `build.py` | Bygger `index.html` av källkoden. |
| `icon.png` | Appikonen (512×512), bäddas in i `index.html`. |
| `tools/mock-firebase.js` | Lokal låtsasserver för Firebase, för tester utan internet. |
| `tools/test_*.py`, `tools/run_group.py` | Acceptanstester (Playwright mot låtsasservern) och en körare som tar om ett fallerat test en gång. |
| `.github/workflows/test.yml` | GitHub Actions: bygger och testar vid varje push till `main`. |
| `CHANGELOG.md` | Versionshistorik. |

### Bygga en ny `index.html`

Kräver Node.js och Python 3.

```bash
npm install
python3 build.py      # skapar index.html
```

Ladda sedan upp den nya `index.html` till GitHub (ersätter den gamla) och tryck **Uppdatera sidan** i appen.

### Så fungerar appen

- **Teknik:** React 18, Recharts (diagram), lucide-react (ikoner), Tailwind CSS 3. Allt paketeras med esbuild till en fil.
- **Data:** Firebase Realtime Database via REST. Live-uppdatering sker med Server-Sent Events (`EventSource`). Inget Firebase-SDK används.
- **Delningskod:** Allt ligger under `diaries/{kod}/…`. Koden fungerar som lösenord (databasreglerna kräver minst 10 tecken). Databasadress och kod sparas bara i enhetens `localStorage` (`nivadagbok-conn`) – de finns **inte** i källkoden.
- **Nycklar:** `entries:ÅÅÅÅ-MM` (JSON-lista med månadens pass), `meta:users` (användare, namn, färger, arkiverade), `ping` (anslutningstest).
- **Pass:** `{id, date, user, sport[], typ[], tid, kansla, cr10, anteckningar}`. Ansträngning anges på Borg CR10 (1–10). Belastning (AU) = tid × ansträngning.
- **Användare:** Flera användare med eget färgtema. Man kan dölja en användare på den egna enheten, eller arkivera för alla.
- **Import/export:** CSV med semikolon: `Datum;Anvandare;Sport;Traningstyp;Tid (min);Anstrangning (1-10);Anteckningar`.

### Ny version – arbetsgång

1. Ändra i `src/`.
2. Höj `APP_VERSION` och `APP_DATE` överst i `src/App.jsx` och lägg till en rad i `CHANGELOG` (samma text läggs i `CHANGELOG.md`).
3. `python3 build.py`.
4. Ladda upp `index.html`, `src/` och `CHANGELOG.md` till GitHub.

### Att tänka på

- **Repot är facit.** Källkoden i `griminell/training` (`main`) gäller. Kopior på andra ställen (till exempel i ett Claude-projekt) kan vara äldre.
- **Automatisk kontroll:** vid varje push bygger GitHub `index.html` och kör testerna. Röd markering (och mejl från GitHub) betyder att senaste versionen bör ses över. Sidan publiceras ändå direkt, eftersom Pages visar `index.html` från `main`.
- Repot är publikt. Lägg aldrig databaskoder eller länkar med `#db=…&code=…` här.
- Hälsouppgifter om barn är känsliga – dela bara kopplingslänken inom familjen.

## English

A shared training diary for the family, built as **a single HTML file** (`index.html`) that can be added to a phone's home screen as a web app. Data is stored live in a Firebase Realtime Database and shared between everyone using the same share code.

**Live:** https://griminell.github.io/training/

### What is in the repo?

| File / folder | Contents |
|---|---|
| `index.html` | The finished app. **This is the file GitHub Pages serves.** Generated by `build.py` – do not edit by hand. |
| `src/App.jsx` | The app itself: log form, month list, statistics, user management, themes, changelog. |
| `src/main.jsx` | Entry point, setup screen and the Firebase storage layer (REST + SSE, no SDK). |
| `src/styles.css` | Tailwind directives and base CSS. |
| `tailwind.config.js` | Tailwind configuration. |
| `build.py` | Builds `index.html` from the source. |
| `icon.png` | The app icon (512×512), embedded into `index.html`. |
| `tools/mock-firebase.js` | Local fake Firebase server for offline testing. |
| `tools/test_*.py`, `tools/run_group.py` | Acceptance tests (Playwright against the fake server) and a runner that retries a failed test once. |
| `.github/workflows/test.yml` | GitHub Actions: builds and tests on every push to `main`. |
| `CHANGELOG.md` | Version history. |

### Building a new `index.html`

Requires Node.js and Python 3.

```bash
npm install
python3 build.py      # creates index.html
```

Then upload the new `index.html` to GitHub (replacing the old one) and press **Uppdatera sidan** ("Refresh page") in the app.

### How it works

- **Stack:** React 18, Recharts (charts), lucide-react (icons), Tailwind CSS 3. Everything is bundled into one file with esbuild.
- **Data:** Firebase Realtime Database over REST. Live updates use Server-Sent Events (`EventSource`). No Firebase SDK.
- **Share code:** Everything lives under `diaries/{code}/…`. The code acts as a password (database rules require at least 10 characters). The database URL and code are stored only in the device's `localStorage` (`nivadagbok-conn`) – they are **not** in the source code.
- **Keys:** `entries:YYYY-MM` (JSON list of the month's sessions), `meta:users` (users, names, colours, archived flag), `ping` (connection test).
- **Entries:** `{id, date, user, sport[], typ[], tid, kansla, cr10, anteckningar}`. Effort uses the Borg CR10 scale (1–10). Load (AU) = duration × effort.
- **Users:** Multiple users, each with a colour theme. A user can be hidden on one device only, or archived for everyone.
- **Import/export:** Semicolon-separated CSV: `Datum;Anvandare;Sport;Traningstyp;Tid (min);Anstrangning (1-10);Anteckningar`.

### Releasing a new version

1. Edit files in `src/`.
2. Bump `APP_VERSION` and `APP_DATE` at the top of `src/App.jsx` and add a line to `CHANGELOG` (put the same text in `CHANGELOG.md`).
3. Run `python3 build.py`.
4. Upload `index.html`, `src/` and `CHANGELOG.md` to GitHub.

### Things to keep in mind

- **The repo is the source of truth.** The code in `griminell/training` (`main`) is what counts; copies elsewhere (for example in a Claude project) may be older.
- **Automatic check:** on every push GitHub builds `index.html` and runs the tests. A red mark (and an e-mail from GitHub) means the latest version should be looked at. The site is still published immediately, since Pages serves `index.html` from `main`.
- The repo is public. Never commit database codes or links containing `#db=…&code=…`.
- Health data about a child is sensitive – only share the connection link within the family.
